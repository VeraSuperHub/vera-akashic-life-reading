# Feedback Refinement Patterns

After an initial reading, invite focused correction. A user's lived response often reveals the sharper version of a chart pattern.

## Workflow

1. Ask which paragraph felt physically charged, flat, wrong, or incomplete.
2. Treat the correction as data, not resistance.
3. Keep the verified chart mechanics, but revise the life-language.
4. Name the refinement explicitly: "I would revise the pattern this way..."
5. Do not defend the first reading. The goal is precision.

## Common Refinements

| User Feedback | Refine Toward |
| --- | --- |
| "I can express myself fine." | The issue may be distribution, reach, resonance, audience, or permission to be widely received rather than basic expression. |
| "I am not afraid of relationships." | Reframe from avoidance to distance regulation, trust pacing, control of vulnerability, or standards for safety. |
| "I do not have trouble starting." | Reframe from initiation to completion, release, publication, visibility, or letting the work leave private control. |
| "This resonates, but for a different reason." | Let the user's context supply the cause while the chart supplies the archetypal shape. |
| "That sounds too negative." | Reduce fatalistic language, locate the gift inside the pattern, and name the agency point. |
| "That sounds too soft." | Move from generic reassurance to a clearer thesis, concrete pattern, and grounded practice. |

## Refinement Prompts

- "Which sentence did your body react to most?"
- "Which part is accurate but named in the wrong way?"
- "Is this more about ability, permission, timing, audience, or safety?"
- "What would be the less dramatic but more precise version of this pattern?"

The best final reading may be a second synthesis, not the first draft.
